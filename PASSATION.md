## 5. ÉCHECS — NE PAS REFAIRE · INCIDENTS
- Le shell réactive conda (`(base)`, `(pre_learn_1)`) et `python` est un alias de `python3` → toujours lancer `.venv/bin/python …` (pytest compris : `.venv/bin/python -m pytest`)
- PyCharm utilise l'interpréteur `pre_learn_1 [3.11]` → le pointer sur `.venv/bin/python`
- `np.array_equal` sur une Random Forest parallèle échoue (ordre des additions) → `assert_allclose(atol=1e-12)`
- Wrapper PyTorch refusé par `Pipeline` sans `fit` → `fit` factice + `__sklearn_is_fitted__`
- Fichiers collés mais non sauvegardés (⌘S) : vérifier sur la machine avant le Temps 1
- Sous la pression du temps, réponses complétées par l'assistant validées ✅ → AS-17 : 🟡, jamais ✅
- Le modèle entraîné (`artifacts/models/`) n'est pas versionné : la CI ne l'a pas → un test qui charge le vrai modèle échoue en CI
- (PR 4) `data/demo/*.json` dépendent du modèle local et de PaySim : la CI ne peut pas les régénérer → pour les refaire, relancer `.venv/bin/python -m scripts.build_demo_cases` en local (≈ 1 min) ; ne jamais les éditer à la main
- (PR 5) `list_events` rend des `StoredAuditEvent(event_id, event)` : les champs sont dans `.event` (`stored.event.action`), pas sur l'objet lui-même (test corrigé avant le commit)
- (PR 5) Tout nouveau fichier dans `src/agent/tools/` (sauf `errors.py`) **doit** déclarer `TOOL_EFFECT`, sinon le test G12 est rouge — ex. `validate_investigation_json.py` (n° 52, PR 6) : `TOOL_EFFECT = "read_only"`

- (PR 6) Le score du brouillon est comparé à 1e-9 près (décision (a)) : le prompt (n° 60) et le scénario « valide » du faux client (n° 56) doivent recopier le score officiel **exact** (`repr(score)`), jamais arrondi, sinon chaque brouillon est rejeté
- (PR 6) Ne pas mettre « 100% » seul dans `prohibited_terms.yaml` : la preuve E2 dit « 100.0% of the origin account balance » (test `test_factual_percentage_is_not_rejected`)
- (PR 7) Ne jamais lever une `LLMError` **dans** un `except` du SDK, ni recopier `str(error)` du SDK : la trace (`__context__`) ou le message ferait sortir la clé (essai de mutation → 2 tests rouges). Garder `kind` et `status_code`, sortir du `try`, puis lever (décision PR 7 (1))
- (PR 7) Un contrôle « pas de `load_config` dans `src/agent/llm/` » par recherche de texte échoue sur les en-têtes « Never does » → lire le code avec `ast` (comme le test G12)
- (PR 7) Ne jamais appeler `load_config()` dans un test sans `env_path` temporaire : il chargerait le vrai `.env` dans `os.environ`
- (PR 8) Une mutation doit casser **toutes** les protections d'un point, sinon elle reste verte sans rien prouver : retirer seulement la garde `isfinite` laisse `allow_nan=False` refuser NaN (vert) ; ajouter `threshold` seulement au contexte est arrêté par la vérification de `render_data_section`. Une mutation qui provoque une `NameError` (import oublié) ne prouve rien non plus
- (PR 8) Ne pas utiliser `str.format` sur le gabarit : les accolades du schéma JSON le casseraient → découpage sur les en-têtes, puis `replace("{{CASE_DATA}}", …, 1)`. Ne pas écrire `<case_data>` dans le texte fixe de la section USER : un test compte une seule balise ouvrante dans `user`
- (PR 9) `retry.py` relance un essai trop lent **même s'il a réussi** (décision (c)) : ne jamais envelopper un outil qui écrit (`write_audit_event`, `intake_case`) dans `run_with_retries`, sinon un essai en retard serait refait (événement d'audit en double, ou `DuplicateSubmissionError`)
- (PR 10) Une seconde soumission d'un cas déjà en revue ou final repart **avant** les étapes (retour anticipé) : une mutation « étape stockée ignorée » seule reste verte sur `test_idempotent_step` ; il faut casser les deux protections (M6) — le test de reprise `test_interrupted_case_resumes_without_redoing_stored_steps` couvre `get_step` seul
- (PR 10) Le test `ast` « pas d'outil qui écrit dans `retry.py` » doit aussi lire `_run_tool_step` (qui transmet `call`) et le corps de `check`, sinon un outil d'écriture passé par là échappe au contrôle
- (PR 11) Compter les lignes d'un CSV avec `csv.reader`, jamais `splitlines()` : une cellule entre guillemets peut contenir un saut de ligne. Une mutation « `ORDER BY` retiré » peut rester verte (SQLite rend souvent l'ordre du `rowid`) → muter en `DESC`
- (PR 11) Les identifiants de cas doivent suivre `CASE-` + 4 chiffres (`parse_case_input`) : un test de bout en bout avec `CASE-E2E` échoue en `ToolInputError` (corrigé avant le commit : `CASE-0900`)
- (PR 11) `append_event` accepte une clé d'étiquette dans `details` et stocke NaN : l'export est la seule barrière pour les deux (ne pas retirer `check_events`)
